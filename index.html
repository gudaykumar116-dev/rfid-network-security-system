Client-Server Architecture

A distributed application model that divides tasks between service providers (servers) and service requesters (clients). The client initiates contact, and the server continuously listens for and processes client requests.

In this project: The RFID reader terminal acts as the Client sending card scan requests, while the central attendance host acts as the Server validating data and returning responses.

TCP/IP Protocol

The Transmission Control Protocol / Internet Protocol suite. TCP provides reliable, connection-oriented data transfer via a 3-way handshake (SYN, SYN-ACK, ACK), ensuring zero packet loss. IP handles addressing and routing packets across the network.

In this project: Guarantees that attendance scan packets are delivered reliably without corruption, loss, or packet duplication over the LAN.

IP Address

A unique 32-bit numerical identifier (IPv4) assigned to every device participating in a computer network using the Internet Protocol for communication. It defines where a device resides on a subnet.

In this project: The RFID Reader client is assigned IP 192.168.1.50, and the Central Server is located at IP 192.168.1.100 on subnet 255.255.255.0.

Port Number

A 16-bit unsigned number (ranging from 0 to 65535) used by transport protocols (TCP/UDP) to identify specific running applications or network processes on a single host.

In this project: The attendance backend service listens specifically on Port 8080, ensuring attendance packets are routed directly to the attendance daemon rather than web traffic (port 80/443).

Socket Programming

A socket is a bidirectional communication endpoint formed by combining an IP Address + Port Number (e.g. 192.168.1.100:8080). Socket APIs allow programs to open connections, stream byte payloads, and exchange acknowledgments.

In this project: The client creates a TCP socket to 192.168.1.100:8080, serializes the RFID ID payload, transmits it, and reads the server's verification status response.
